# 逻辑确认 Skill

在修改代码前，必须先和用户确认实现逻辑。

## 执行步骤

### 第 1 步：用围棋语言描述功能

用用户能理解的围棋术语描述要实现的功能，不涉及代码细节。

格式：
```
## 功能：[功能名称]

### 场景
[用围棋场景描述，比如：你在野狐下棋时...]

### 触发条件
[什么情况下会触发这个功能]

### 执行动作
[触发后会发生什么]

### 预期结果
[最终达到什么效果]
```

### 第 2 步：等待用户确认

明确询问用户：
- "以上理解是否正确？"
- "有需要补充或修正的吗？"

### 第 3 步：用户确认后才写代码

只有在用户明确说"正确"或"可以开始"后，才开始修改代码。

## 重要原则

1. **先逻辑后代码** - 永远不要在逻辑未确认前写代码
2. **围棋语言优先** - 用"黑方""白方""镰刀""落子"等围棋术语，不用"变量""函数""参数"
3. **场景化描述** - 用具体的对局场景来描述，而不是抽象的技术流程
4. **确认再行动** - 有任何不确定的地方，先问用户
