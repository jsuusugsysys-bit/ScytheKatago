# 自定义要求

本文档包含与 Claude Code 交互时的自定义要求和偏好设置。

## 用户背景

### ⚠️ 重要：用户是计算机新手

**交流要求：**
- 使用中文交流
- 提供详细、清晰的解释
- 避免使用专业术语，或在使用时提供解释
- 提供具体的命令和步骤，而非抽象的建议
- 耐心解释"为什么"而不仅仅是"怎么做"
- 如果出现错误，提供详细的排查步骤和可能的原因

**示例：**

❌ **不好的回答：**
"你需要重构这个函数以提高性能。"

✅ **好的回答：**
"这个函数每次走棋都会被调用（热路径），所以需要优化性能。具体来说：
1. 避免在函数中创建新的对象（会分配内存，很慢）
2. 使用简单的 if 判断而不是调用其他函数
3. 这样可以让 AI 思考速度更快

我来帮你修改代码..."

## 思维模式

### 使用 ultrathink 模式

**要求：** 在处理复杂问题时，使用深度思考模式

**适用场景：**
- 设计新功能
- 调试复杂问题
- 性能优化
- 架构决策

**思考内容：**
- 分析问题的根本原因
- 考虑多种解决方案
- 评估每种方案的优缺点
- 选择最适合新手的方案
- 预测可能的问题

**示例：**
```
问题：GUI 更新太慢，卡顿

思考过程：
1. 可能原因：
   - 频繁查询 GTP 状态（轮询）
   - 在 UI 线程中执行耗时操作
   - 重绘次数过多

2. 解决方案：
   A. 减少查询频率 - 简单但治标不治本
   B. 改为事件驱动 - 最佳方案，但需要修改架构
   C. 使用后台线程 - 折中方案，易于实现

3. 推荐方案 B（事件驱动）：
   - 仅在走棋后查询状态
   - 不使用定时器轮询
   - 性能最好，代码最清晰

4. 实施步骤：
   - 删除定时器代码
   - 在 onMoveMade() 中调用 updateStatus()
   - 测试验证
```

## 工作流程偏好

### 代码修改前

**必须先读取文件：**
- 绝不对未读取的代码提出修改建议
- 理解现有代码结构
- 确认修改位置正确

**使用 MCP 工具：**
- 使用 Context7 等工具分析代码
- 获取优化建议
- 检查代码质量

### 代码修改时

**批量修改：**
- C++ 修改：使用 `compile.bat` 快速重建
- Java 修改：批量修改后再编译（Maven 需要 3 分钟）
- 避免频繁编译

**解释修改：**
- 说明为什么要这样修改
- 解释修改后的效果
- 提供测试方法

### 代码修改后

**验证修改：**
- 确保代码能编译
- 运行基本测试
- 检查是否有新的问题

**记录修改：**
- 更新 PROJECT.md 中的进度
- 如果完成了某个子目标，标记为 ✅
- 记录遇到的问题和解决方法

## 错误处理偏好

### 遇到错误时

**详细说明：**
1. 错误是什么
2. 为什么会出现这个错误
3. 如何解决（提供具体步骤）
4. 如何避免再次出现

**示例：**
```
错误：找不到 ZLIB

原因：
ZLIB 库没有编译，或者路径不正确。
KataGo 需要 ZLIB 来压缩神经网络文件。

解决步骤：
1. 检查 D:\ScytheKatago\zlib\build\Release\ 目录
2. 如果没有 zs.lib 文件，运行 build.bat 重新编译
3. 如果有文件但还是报错，检查 CMakeLists.txt 中的路径

预防措施：
首次构建时使用 build.bat 而不是 compile.bat
```

## 代码示例偏好

### 提供代码时

**包含注释：**
```cpp
// 检查是否可以使用镰刀
// 条件：11x11 棋盘，第 11-49 手，有剩余镰刀
if (boardSize == 11 && moveNum >= 11 && moveNum <= 49 && blackScythes > 0) {
    // 可以使用镰刀
    return true;
}
```

**对比新旧代码：**
```cpp
// 旧代码（有问题）
if (canUseScythe()) {  // 每次都调用函数，慢
    // ...
}

// 新代码（优化后）
if (moveNum >= 11 && moveNum <= 49 && blackScythes > 0) {  // 直接判断，快
    // ...
}
```

**解释为什么这样写：**
```cpp
// 使用引用传递，避免拷贝整个 Board 对象
// Board 对象很大（包含整个棋盘状态），拷贝很慢
void processBoard(const Board& board) {  // 注意这里的 &
    // ...
}
```
