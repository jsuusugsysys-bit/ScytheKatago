# 镰刀功能自动化测试套件

本测试套件用于全面测试 ScytheKatago 项目的镰刀功能。

## 测试概述

镰刀规则：
- **棋盘大小**：仅在 11x11 棋盘生效
- **可用时机**：仅在第 11-49 手期间可用
- **使用次数**：每方有 3 次镰刀机会
- **连击效果**：每次镰刀允许连续下 3 手

## 测试文件说明

### 1. test_basic.txt - 基本功能测试
**测试目标**：验证镰刀的基本触发和连击功能

**测试场景**：
- 黑方在第 11 手触发镰刀
- 验证连续下 3 手
- 验证镰刀数量减少

**预期结果**：
- 初始状态：黑方 3 次，白方 3 次
- 触发后：黑方连续下 3 手
- 连击结束：黑方 2 次，白方 3 次

### 2. test_boundary.txt - 边界条件测试
**测试目标**：验证镰刀在不同手数的可用性

**测试场景**：
- 第 10 手尝试触发（不可用）
- 第 11 手触发（可用）
- 第 49 手触发（最后机会）
- 第 50 手尝试触发（不可用）

**预期结果**：
- 第 10 手：镰刀不触发或无效
- 第 11 手：镰刀成功触发
- 第 49 手：镰刀成功触发
- 第 50 手：镰刀不触发

### 3. test_combo.txt - 连击逻辑测试
**测试目标**：验证连击期间不换手，连击后正常换手

**测试场景**：
- 黑方触发镰刀，验证连续 3 手都是黑方
- 连击结束后验证轮到白方
- 白方触发镰刀，验证连续 3 手都是白方
- 连击结束后验证轮到黑方

**预期结果**：
- 连击期间：同一方连续下 3 手
- 连击结束：正常换手

### 4. test_count.txt - 镰刀数量测试
**测试目标**：验证镰刀次数限制（每方 3 次）

**测试场景**：
- 黑方连续使用 3 次镰刀
- 尝试使用第 4 次（应该失败）

**预期结果**：
- 第 1 次：成功，黑方剩余 2 次
- 第 2 次：成功，黑方剩余 1 次
- 第 3 次：成功，黑方剩余 0 次
- 第 4 次：失败，镰刀不触发

### 5. test_both_players.txt - 双方测试
**测试目标**：验证黑白双方都能正确使用镰刀

**测试场景**：
- 黑白双方交替使用镰刀
- 验证各自的镰刀数独立计数
- 双方都用完 3 次后尝试再次使用

**预期结果**：
- 黑白双方镰刀数独立计数
- 每方都能使用 3 次
- 用完后无法再触发

### 6. test_board_size.txt - 棋盘大小测试
**测试目标**：验证镰刀仅在 11x11 棋盘生效

**测试场景**：
- 在 9x9 棋盘尝试触发（应该失败）
- 在 19x19 棋盘尝试触发（应该失败）
- 在 11x11 棋盘触发（应该成功）

**预期结果**：
- 9x9 和 19x19：镰刀不触发
- 11x11：镰刀正常触发

### 7. test_reset.txt - 重置功能测试
**测试目标**：验证镰刀重置命令

**测试场景**：
- 使用镰刀后重置
- 验证镰刀数恢复到 3
- 测试设置任意数量

**预期结果**：
- 重置后镰刀数恢复
- 可以设置任意数量
- 设置为 0 后无法使用

## 运行测试

### 方法 1：运行所有测试（推荐）

```batch
run_all_tests.bat
```

这将：
1. 自动运行所有 7 个测试
2. 生成详细的测试报告
3. 保存每个测试的输出和错误日志
4. 在 `results\test_<时间戳>\` 目录下保存结果

### 方法 2：运行单个测试

```batch
run_single_test.bat test_basic.txt
```

这将在控制台直接显示测试输出，方便调试。

### 方法 3：手动运行测试


## 测试结果解读

### 成功的测试输出示例

```
= {"blackScythes":3,"whiteScythes":3,"scytheCombo":0,"nextPlayer":"B","isComboActive":false,"moveNumber":10,"canUseScythe":true}
```

关键字段：
- `blackScythes`: 黑方剩余镰刀数（0-3）
- `whiteScythes`: 白方剩余镰刀数（0-3）
- `scytheCombo`: 当前连击剩余手数（0-2）
- `isComboActive`: 是否在连击中（true/false）
- `moveNumber`: 当前手数
- `canUseScythe`: 是否可使用镰刀（第 11-49 手）

### 常见问题

**问题 1：测试失败，提示找不到 katago.exe**
- **原因**：KataGo 未编译或路径不正确
- **解决方案**：运行 `build.bat` 或 `compile.bat` 编译项目

**问题 2：测试运行缓慢**
- **原因**：神经网络计算需要时间
- **解决方案**：
  - 减少 `scythe_config.cfg` 中的 `maxVisits`（如改为 100）
  - 使用更小的神经网络（如 15b 或 20b）

**问题 3：镰刀未触发**
- **原因**：可能不满足触发条件
- **检查**：
  - 棋盘是否为 11x11
  - 手数是否在 11-49 之间
  - 镰刀数是否大于 0

**问题 4：连击未生效**
- **原因**：可能是代码逻辑问题
- **检查**：
  - 查看 `boardhistory.cpp` 中的 `makeBoardMoveAssumeLegal()` 函数
  - 验证 `scytheCombo` 变量是否正确递减

## 测试报告

运行 `run_all_tests.bat` 后，测试报告保存在：
```
test_scythe_suite\results\test_<时间戳>\test_report.txt
```

报告包含：
- 测试时间
- 测试统计（总数、通过、失败）
- 每个测试的详细结果
- 输出和错误日志文件路径

## 扩展测试

如需添加新测试：

1. 创建新的 `.txt` 文件（GTP 命令序列）
2. 在 `run_all_tests.bat` 的 `TEST_FILES` 变量中添加文件名
3. 在本 README 中添加测试说明

### GTP 命令参考

常用镰刀相关命令：
```
boardsize 11                              # 设置棋盘大小
clear_board                               # 清空棋盘
komi 7.5                                  # 设置贴目
play black D4                             # 黑方下子
play white D8                             # 白方下子
kata-get-scythe-status                    # 查询镰刀状态（JSON）
kata-set-param scythe_trigger true        # 触发镰刀
kata-set-param scythe_count_black 3       # 设置黑方镰刀数
kata-set-param scythe_count_white 3       # 设置白方镰刀数
genmove black                             # 黑方生成走法
genmove white                             # 白方生成走法
quit                                      # 退出
```

## 性能基准

在标准配置下（CPU: Intel i7, maxVisits: 500）：
- 单个测试运行时间：约 2-5 分钟
- 完整测试套件：约 15-30 分钟

优化建议：
- 减少 `maxVisits` 可加快测试速度
- 使用 GPU 版本（TensorRT）可显著提升性能
